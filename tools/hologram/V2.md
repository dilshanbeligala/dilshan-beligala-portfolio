# Neural hologram V2 — refinement and validation

## Recoverable checkpoint

`e3c0102` preserves the entire working V1 portfolio and generated assets before refinement. V2 changes are left uncommitted for review. Local V1 screenshots and previews are additionally retained in ignored `private/v1/`.

## Audit

V1 image-to-mesh XY alignment was correct and its tiny idle displacement was not the main cause of lost likeness. The main problems were:

- Replacement sampling created clusters: 24,000 points covered only 13,151 unique rounded source pixels.
- Monochrome cyan coloring discarded useful photographic chromatic/tonal detail.
- Additive particle blending and disabled depth testing weakened shadows and let overlapping points brighten each other.
- There was no photographic layer to retain eyes, eyebrows, lips and facial hair.
- The nearest-landmark hair shell and linear facial interpolation needed smoother transitions.

## Reconstruction and sampling

The same verified Google model detects the same 478 landmarks locally. XY proportions are unchanged. Bounded Clough–Tocher interpolation improves continuity, with overshoot limited to 1.2 source pixels relative to the linear depth estimate. Mild smoothing and a continuous transition to a shallow extrapolated scalp reduce depth ridges. Estimated depth is compressed to 72% of its original magnitude to favor front-facing likeness. This is an artistic relief, not measured head geometry.

OpenCV GrabCut refines a narrow band around the existing portrait-specific silhouette. It uses the photograph and locally seeded masks; no new model or service is involved. Hair depth remains conservative and layered, while the original texture retains its visible strands.

A deterministic scrambled Halton sequence provides progressive spatial coverage. Detected feature contours and image gradients guide rejection density. A local spacing exclusion prevents replacement clumps. The resulting 15,641 points use smaller sizes around eyes, brows, nose and lips. No point count was increased to disguise geometry problems.

## Hybrid renderer

A 7,128-vertex source-aligned grid shares the point cloud's relief and head transform. A lossless 143 × 197 RGBA crop of the original photograph maps onto its UVs. Its opacity ranges from 0.42 in smooth regions to 0.78 around facial features, then fades at the silhouette/neck and during assembly. It is not an opaque billboard. Texture and particle colors are converted from sRGB to linear color before output conversion.

The facial layer uses subtle cool-white frontal shading, cyan/violet rim accents, and a narrow restrained scan. Source tones remain partially visible. Smaller normally blended particles sit just in front of the mesh; both layers depth-test, and the detail surface writes depth. Additive blending is reserved for the sparse atmosphere and nearly invisible contour accents. Four draw calls replace V1's three; no postprocessing is added.

Head tracking remains bounded to ±5° yaw / ±3° pitch with delta-based damping. The detail surface and points share subpixel breathing. Facial points have no independent idle displacement that would break texture alignment. Touch-only devices do not track pointer motion.

Initial quality uses input capabilities, reduced-motion preference, save-data preference, and WebGL capability rather than screen width. Fine-pointer devices start at medium (11,000 points); one promotion to high (15,641) can follow measured stable frames. Sustained slow frames lower quality with a cooldown. Low uses 4,500 points and DPR 1; medium caps DPR at 1.25 and high at 1.5. Touch-only, reduced-motion and save-data users receive the static hybrid portrait. These are budgets, not performance guarantees.

The fallback uses a versioned URL, `portrait-fallback-v2.webp`, to prevent Next Image's optimized V1 image cache from hiding the new asset. It is generated locally from the same source/detail treatment and point samples. Context loss, invalid/missing assets, shader failure, and JavaScript absence preserve the recognizable static portrait. Loading, GPU disposal, bitmap closure, fetch cancellation, and visibility pausing remain in place.

## Assets and formats

- `facial-particles.bin`: V2 `DBHP` header (version 2, count, stride 24). Each record has float32 XYZ, source RGB bytes, size byte, float32 seed, float32 feature weight.
- `facial-detail.bin`: `DBHS` header (version 1, columns, rows), then float32 XYZ, UV, feature per grid vertex. The runtime constructs regular-grid indices and normals once.
- `portrait-detail.webp`: original-photo color and alpha crop, approximately 28 KB; no generated facial pixels.
- `facial-contours.bin`: updated source-aligned contour positions.
- `facial-surface.glb`: reusable masked relief with embedded original photographic texture; not loaded by the site.
- `portrait-fallback-v2.webp`: optimized hybrid fallback, approximately 56 KB, down from V1's 112 KB.
- `manifest.json`: source/model/asset hashes, dimensions, byte sizes, interpolation diagnostic, and limitations.

Direct runtime geometry/detail downloads total approximately 578 KB before HTTP compression, compared with approximately 483 KB for V1's geometry. The photographic detail adds useful information with fewer particles. Python and model weights remain excluded from the website runtime. No new dependencies or AI models were installed for V2.

## Verification and limits

`npm run lint`, `npx tsc --noEmit`, and `npm run build` pass. Geometry checks cover binary dimensions, feature ranges, UV/normal counts, malformed buffers, and disposal. Browser checks cover responsive views, pointer screenshots, offscreen pause, reduced motion, context loss, unavailable WebGL, JavaScript disabled, mobile menu Escape/focus restoration, anchors, and external network requests.

The measured local desktop sample used 90 requestAnimationFrame intervals: mean approximately 16.67 ms, p95 approximately 16.8 ms. This is browser frame scheduling on this machine, not GPU timing, a Lighthouse score, or a real-device guarantee. See the latest `private/browser/report.json` for the final values.

The source remains a 400 × 400 photograph, with the head occupying only part of it. Fine details, hidden surfaces and accurate hair volume cannot be reconstructed from it. The result remains approximate front-facing 2.5D with photographic detail; it is not a photorealistic 360° face scan. Existing photographic lighting remains partly baked in. Safari, real phones/tablets, sustained thermal/battery behavior and assistive-technology checks still require manual verification.
